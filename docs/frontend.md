# G-VISTA — Frontend

Governs the client application: stack, routing/page inventory, and what's real vs. mock per page. Product scope, goals, personas, and the hackathon compliance context live in [prd.md](prd.md).

Stack: **React 19 + Vite 6**, `react-router-dom` for client-side routing, plain CSS per component (no CSS framework/tokens system yet), Leaflet/`react-leaflet` for mapping.

---

## 0. Why this doc was rewritten (2026-09-14, updated same day after the completion pass below)

This file used to describe a Next.js + TypeScript + Zustand app built earlier in this project. The team decided to standardize on a teammate's separately-developed React/Vite app instead (`client/`, previously `frontend/harsif/`) — it already had a working Camera Registry, Dashboard, and Investigation page with real design/UX investment, where the Next.js app had only Dashboard and Live Cameras built out. The Next.js app was archived at `contrib/nextjs-frontend-archive/` rather than deleted outright at first; it was removed from the repo entirely on 2026-09-14 once its owner had it stored externally (prd.md §15) — see §6 for what was and wasn't ported out of it first.

**This doc now describes `client/` as it actually is**, not an aspirational spec. Where prd.md's page requirements aren't yet met by the current code, that's called out explicitly in §5 rather than glossed over — same honesty convention backend.md uses.

Later the same day, every page identified in §5 as mock-only or stub was wired to the real backend — the one deliberate exception was `CameraMap.jsx`, then flagged as a known remaining gap, and `Model3.jsx`, which stays intentionally unbuilt (a decision, not an oversight — see its entry in §5).

**Still later the same day** (a third pass), the five items the team explicitly asked for next were built: `CameraMap.jsx` is now real too (§5), Model 1's gap-analysis report is surfaced (§5, `CameraRegistry.jsx`), a new System & Network page exists (§3/§5), real WHEP/HLS-style live playback is wired via `hls.js` (§5, `LiveCameras.jsx`), and a real Hindi/Gujarati translation system covers the app shell and every page header (§2/§5, `src/i18n/`).

**A fourth pass, still the same day**, closed the remaining six items: a real footer status strip, `prefers-reduced-motion` handling, a real contrast-audited design-token system (§7), a real accessibility pass driven by an actual `axe-core` scan (§8), a real mobile-layout fix driven by an actual 375px screenshot (§8), and JS bundle code-splitting cutting the production entry chunk from 1.2 MB to ~340 KB (§8). Also caught and fixed along the way: a CORS gap for Vite's auto-incremented dev ports, and a mock-data shape mismatch that crashed two pages outright whenever mock mode activated (§8). §5 below is the current, up-to-date status — read it, not this paragraph, for what's actually built.

## 4. API integration (`src/api/client.js`) — rebuilt 2026-09-14

The client used to call `/api/intelligence/*` and `/api/operations/*` — endpoints that don't exist on the real backend (`server/`); those names only ever existed on a teammate's separately-evolving `contrib/aneesh/backend/`, which this project is **not** using as production (see backend.md's header and prd.md §15 — `server/` is production because it has the auth/RBAC/watchlist/alert/investigation work `contrib/aneesh/backend/` doesn't). The client is now wired against `server/`'s real routes:

- **Auth** — `login()`/`logout()`/`getCurrentUser()` against `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`. The JWT is stored in `localStorage` and attached as `Authorization: Bearer` on every authenticated call. `LoginScreen.jsx` used to "succeed" for any non-empty username/password via a fake `setTimeout` — that was a real security bug (fake auth passing as real), not just an unfinished feature, and is fixed.
- **Route protection** — `api.hasSession()` covers a real token or a deliberate, honestly-labelled mock-mode login (when no backend is reachable at login time) — see `App.jsx`.
- **Cameras** — `GET/POST /api/cameras/`, gap-analysis, per-camera adapter health (`/api/cameras/{uid}/adapter/health` — note this is mounted under `/api/cameras`, not a separate `/api/adapters` prefix, a real mismatch the old client had).
- **Watchlists** — `GET/POST /api/watchlists/`. New in this pass — `Watchlists.jsx` is the first page built directly against this.
- **Alerts** — `GET /api/alerts/`, per-alert fetch, status PATCH, and opening an investigation from an alert (`POST /api/alerts/{uid}/investigation`).
- **Investigations** — full CRUD plus `timeline`, `trace` (the graded map-trace flow), and `evidence` sub-resources.
- **Live events** — `subscribeToLiveEvents()` opens a real `EventSource` against `GET /api/streams/events/stream` (deliberately unauthenticated on the backend, matching how browser `EventSource` can't send custom headers). Consumed by `Dashboard.jsx`'s "Live AI Events (this session)" counter and `LiveCameras.jsx`'s event feed.
- **Stream start/stop (new)** — `startStream()`/`stopStream()`/`getStreamStatus()` against real `POST/GET /api/streams/{camera_id}/[start|stop|status]`. `startStream()` spawns a real FFmpeg subprocess server-side (`server/video/ffmpeg_runner.py`) transcoding the camera's real `rtsp_url`; throws the backend's real error (e.g. "Camera not found or RTSP URL missing", or a 500 if ffmpeg genuinely isn't available) rather than a fabricated success.
- **AI detections** — still honestly mock-only (`getAIDetections()`): the real backend has no "list current detections" endpoint (`server/routers/ai.py` is per-frame `analyze-frame` only), so faking a live feed here would misrepresent what's actually running.
- **Admin** — `getUsers()`/`createUser()` (`/api/auth/users`), `getAuditLog()` (`/api/admin/audit-log` — unwraps its `{entries: [...]}` wrapper), `getFacialRecognitionStatus()`/`setFacialRecognitionAuthorization()` (`/api/admin/facial-recognition[/authorize]`). These three throw a real error on a non-2xx HTTP response (e.g. a genuine 403 for a non-admin account) rather than silently falling back to an empty list — a permission denial and "zero real rows" must never look the same to whoever's looking at the Administration page. Network-unreachable still falls back to mock, same as everywhere else.

Every method falls back to mock data (`src/api/mockData.js`) when the backend is unreachable, and `api.getMode()` reports which mode is active — this is what backs the Topbar's LIVE/MOCK pill, so the distinction is never silently hidden from the user (same honesty rule prd.md §0.1 requires for the submission demo).

## 7. Design system

`src/styles/theme.css` holds a real, contrast-audited token set — `--bg-primary`/`--bg-secondary`/`--text-primary`/`--text-secondary`/`--accent`/`--accent-text`/`--border-color`, plus five semantic status tokens (`--status-success/warning/danger/info/neutral`, each with a matching `-bg` tint) mirroring `StatusBadge.css`'s five variants. `AccessibilityBar.css`'s `html[data-contrast='high']` block redefines every one of them to an AAA-checked palette.

**`client/scripts/contrast-audit.mjs`** (`npm run audit:contrast`) computes real WCAG 2.1 contrast ratios for every token pair actually used as text — not a claimed "AAA-checked" without the math run. It found and drove real fixes: `--accent` (`#0284c7`) was 4.10:1 with white text, failing AA at the normal-text sizes it's used at throughout the app (nav labels, tab text, dozens of buttons) — darkened to `#0278b5` (4.82:1), which also fixed every existing `background-color: var(--accent)` button site without hunting each one individually. 17/17 pairs currently pass their stated target (AA 4.5:1 for normal text, AAA 7:1 where claimed).

This is a real, working token system, not the full institutional-palette/typography-scale system the archived Next.js app had (§6) — it covers color only, scoped to what an actual audit could verify, rather than re-describing a broader system whose source is no longer in this repo.

## 8. Accessibility, mobile layout, and bundle size (fourth pass, same day)

A team follow-up to the third pass named six further gaps: no footer status strip, no `prefers-reduced-motion` handling, no formal design-token/contrast audit (§7, above), no screen-reader pass, no mobile/responsive check, and a single 610 KB JS chunk. All six were addressed and verified by actually running the app — a real Playwright + `axe-core` scan (`wcag2a`/`wcag2aa`/`best-practice` rules) across all 9 pages plus 3 modal/form states, a real 375px-viewport screenshot pass, and a real production build.

- **Footer status strip** — `Footer.jsx`/`Footer.css`, mounted in `App.jsx` below `.app-body`. Reuses the same `api.checkBackendAvailability()`/`getMode()` Topbar's pill already calls (one source of truth, not a second independent check). `Layout.css`'s `.app-body` height was a hardcoded `calc(100vh - 60px)` that only worked because nothing came after it — switched to `flex: 1; min-height: 0` so the footer (and anything else added later) doesn't get pushed off-screen.
- **`prefers-reduced-motion`** — one rule in `global.css` caps every animation/transition duration to ~0 when set, rather than requiring each of the 12 CSS files with animations to opt in individually (the way that kind of rule silently rots as new CSS gets added).
- **Design tokens / contrast audit** — §7, above.
- **Screen-reader pass** — real findings from a real axe-core run, not a manual guess: `CameraMap.jsx`'s Leaflet markers had `role="button" tabindex="0"` (Leaflet's own keyboard handling) with zero accessible name on all 25+ rendered markers — `L.DivIcon` markers don't forward a Marker's `alt` prop to the DOM the way `L.Icon` markers do, so `aria-label` is now set directly on the real DOM element via the marker's `add` event handler. `DataTable.jsx`'s filter and page-size `<select>`s, `LiveCameras.jsx`'s three filter `<select>`s, and `Administration.jsx`'s add-user form fields all lacked accessible names (critical-impact axe rule) — fixed with `aria-label`/`htmlFor`+`id` pairs. `CameraRegistry.jsx`'s 12-field add-camera form had visible `<label>` text sitting as an unassociated sibling of its `<input>`/`<select>` for every field except one checkbox — added real `htmlFor`/`id` pairs throughout. Both modal dialogs (`role="dialog"`) lacked `aria-labelledby`. `DataTable.jsx`'s internal title heading was an `<h3>` sitting directly under each page's `<h1>` (skipping `<h2>`) — changed to `<h2>`. A `<span aria-label>` with no ARIA role (`LoginScreen.jsx`'s status-pulse dot) didn't reliably expose that name — fixed with `role="img"` in the login-page pass (§9).
- **Mobile/responsive check** — a real 375px screenshot was the first time this app had actually been checked at phone width, and it surfaced two real, unrelated bugs: (1) `Sidebar.jsx`'s 260px nav had no responsive handling at all and permanently occupied most of a phone screen with no way to collapse it — now a real off-canvas overlay below 880px (`Sidebar.css`), opened via a hamburger button in `Topbar.jsx` and closed by its backdrop, a nav click, or a route change (state lifted to `App.jsx`, closes automatically on navigation). (2) Most of `Topbar.jsx`'s own classes (`topbar-brand`, `topbar-center`, `pipeline-indicator-group`, `engine-mode-pill`, and eight others) had **no CSS defined anywhere** — real, unstyled markup was spilling and overlapping the sidebar at every viewport width, not just narrow ones; `Topbar.css` now styles all of it, with the pipeline-indicator strip and brand subtitle hidden below 880px rather than wrapped illegibly.
- **JS bundle code-splitting** — `App.jsx`'s nine route pages converted from static imports to `React.lazy()` + one `<Suspense>` boundary around `<Routes>`. The single 1.2 MB production chunk Vite's own build warned about is now a ~340 KB main entry chunk plus one per-route chunk fetched only on navigation; `vite.config.js`'s `chunkSizeWarningLimit` raised to 650 to reflect that the one chunk still over 500 KB (`LiveCameras.jsx` + `hls.js`, a genuinely large library) is lazy and never touches first load.

Also found and fixed along the way, not on the original list: **`server/core/config.py`'s `CORS_ORIGINS`** didn't include port 5174/5175 (Vite auto-increments past 5173 when it's already taken, e.g. a second `npm run dev`) — every real API call from such a session silently failed CORS preflight, indistinguishable from "backend not running." And **`src/api/mockData.js`'s `MOCK_OPERATIONAL_ALERTS`** still used the pre-rewrite fabricated shape (`alert_type`/`subject`/`title`/fake `officer_id`/`eta` fields, docs/prd.md §15) instead of the real `AlertResponse` shape (`type`/`entity`/`camera_uid`) every real-data component now expects — whenever mock mode activated (a real, supported fallback, not a corner case), `Analytics.jsx`/`Investigation.jsx` crashed outright on `undefined.replace(...)`, taking `<main>` and every `<h1>` down with them. Rewritten to the real shape and verified with mock mode forced on via a blocked-network Playwright run: zero page errors, real headings and landmarks render on every page.
